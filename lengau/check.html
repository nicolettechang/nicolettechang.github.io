ls -lh shows how big a file is. du (disk usage) adds up the space a folder takes, so it can take a while on big folders.

The commands below put a few pieces together:

du -sh
-s gives one total per folder instead of a line for every subfolder; -h shows sizes as KB, MB and GB.
~/* ~/.[!.]*
everything in your home folder, then the hidden files and folders, whose names start with a dot.
2>/dev/null
throws away error messages such as Permission denied: 2> redirects the errors, and /dev/null discards whatever is sent to it.
> file.txt
sends the output into a file instead of the screen, as the job under It stopped with Killed does with ~/sizes_scratch.txt. > replaces the file; >> adds to its end.
|
a pipe: passes the output of one command on to the next.
sort -h
sorts by size. sort -h sorts from smallest to largest; sort -hr reverses the order so largest first.

Decide what to keep

Remember anything you leave on the cluster will be gone forever. This guide can help you add each folder you want to keep in a download list. This list will be used to generate the download commands.

What to keep and what to let go?

fileskeeplet go
code code, scripts, notebooks (and push them to a git remote too), plus build files and the module list you compiled with *.o and *.mod files, and executables you can rebuild
settings namelists and config files, job scripts (*.pbs), and a record of your modules, conda environments, crontab and settings files such as .bashrc installed conda environments: keep the recipe, rebuild them later
model inputs grids, initial and boundary conditions, forcing you made yourself public data, anything you can easily re-download (ERA5, CMIP6, satellite products, …)
model runs reference runs, output for a paper or thesis, and restart files you would need to carry on a run test and benchmark runs, TMPDIR_* and other working folders
datasets processed data, data you will need for the next 3 months, anything that took a long time to make anything you can easily re-run or download again

If you need a backup of your data in addition to the files you're downloading: let's chat.

Explainer Why let executables go?

An executable built on Lengau is tied to Lengau: it was linked against Lengau's compilers, MPI and libraries, so it usually won't run on your laptop or on the next cluster. You will rebuild it from source there. That is why the build files (Makefiles, arch or config files, compile scripts) and the output of module list are worth keeping: they are the recipe.

Keep an executable if a run behind a paper or thesis chapter used it, so there is a record of exactly what made the results, or if you can no longer get its source code.

Compress your data, or not?

To save storage space, you can choose to compress your data. However, this only works for certain types of data.

      Trim precision

      Model output is rarely accurate to every digit it is written with. Keeping 3 significant digits throws the rest away for good, so check with your supervisor first. It only saves space in a compressed file, which -7 -L 1 writes:

    4. 4 drops the rest

      Extract variables

      Keep only the fields you use: often the biggest saving. See what is in a file:

      Then copy just the variables you want, by the names it shows. Name nav_lat and nav_lon too: ncks only brings the grid along when the variables list it under coordinates, and without it you can't tell where the data is. Depth and time come along on their own.

Explainer Why not all of .ssh?

.ssh also holds your private keys (id_rsa, id_ed25519). Anyone with one of those can log in as you wherever it is accepted, so it should not sit on an external drive. Make new keys on the next system instead, and add the new public key wherever the old one was used, such as GitHub.
